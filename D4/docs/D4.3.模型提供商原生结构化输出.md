# 模型提供商原生结构化输出
`entity()`是将错误信息附加到提示词中要求模型做出响应，属于响应侧约束

而`useProviderStructuredOutput()`是在API层参数对模型做出约束，属于请求端约束

`entity()`方法中接收`Consumer<EntityParamSpec>`中的而`useProviderStructuredOutput()`来提供原生结构化支持

```java
ActorsFilms films = chatClient.prompt()
    .user("Generate the filmography for a random actor.")
    .call()
    .entity(ActorsFilms.class, spec -> spec.useProviderStructuredOutput());
```

与`validateScheme()`的区别：
1. 提示词中不再带有格式化相关的信息，更加简洁
2. 作为API级字段在调用模型时生效
3. 模型必须按照给定的格式做出响应

由于完全是模型内部做出的优化，好处在于：
1. 更高的可靠性
2. 更简洁
3. 更好的性能

Spring AI通过检测聊天模型的选项是否实现了`StructuredOutputChatOptions`接口，如果实现了，说明支持原生结构化模型，如果没实现，说明不支持，直接忽略该选项

目前仅有如下模型厂商支持：
- OpenAI
- Anthropic
- Google GenAI
- Mistral AI
- Ollama

该功能，或者说该方法是默认不启用的，只有调用时启用，主要目的是为了兼容大多数新老模型
