# 分块策略对比
本文旨在分析对比ETL流水线中`TokenTextSplitter`的分块策略

## 素材
以markdown文件测试：

[验证素材-星槎精工2026年度经营与财务分析报告.md](../resources/%E9%AA%8C%E8%AF%81%E7%B4%A0%E6%9D%90-%E6%98%9F%E6%A7%8E%E7%B2%BE%E5%B7%A52026%E5%B9%B4%E5%BA%A6%E7%BB%8F%E8%90%A5%E4%B8%8E%E8%B4%A2%E5%8A%A1%E5%88%86%E6%9E%90%E6%8A%A5%E5%91%8A.md)

文件细节：
- 原文件总长7261 字符 / 4531 个汉字 / 约 5900 token / 24 个章节
- 除第十章节外每个章节平均只有120个文字（约156token），也就是说不管chunk size设为200/500/100，除第十章节外的章节被切分的块应该是一致的
- 第十章节1764 汉字（约 2293 token，当然不同模型对汉字的token处理是不同的，会有细微差异），所以chunk size设为200，应该切分成大约12块，500则对应大约5块，1000则对应大约3块

示例代码：
MyMarkdownReader：
```java
@Component
public class MyMarkdownReader {
    private static final Pattern HEADING = Pattern.compile("^(#{1,6})\\s+(.*)$");

    private Resource resource;

    public MyMarkdownReader(@Value("classpath:reader/验证素材-星槎精工2026年度经营与财务分析报告.md") Resource resource) {
        this.resource = resource;
    }

    public List<Document> loadMarkdown() {
        MarkdownDocumentReaderConfig markdownDocumentReaderConfig = MarkdownDocumentReaderConfig.builder()
                .withHorizontalRuleCreateDocument(true)
                .withIncludeBlockquote(false)
                .withIncludeCodeBlock(false)
                .withAdditionalMetadata("filename", "code.md")
                .build();

        MarkdownDocumentReader markdownDocumentReader = new MarkdownDocumentReader(this.resource, markdownDocumentReaderConfig);
        return markdownDocumentReader.get();
    }
}
```

MyTokenTextSplitter：
```java
@Component
public class MyTokenTextSplitter {
    public List<Document> splitDocuments(List<Document> documents) {
        TokenTextSplitter tokenTextSplitter = TokenTextSplitter.builder()
                .withChunkSize(1000)
                .withMinChunkSizeChars(0)
                .withPunctuationMarks(List.of('。', '！', '？', '；', '\n'))
                .withMinChunkLengthToEmbed(0)
                .build();
        return tokenTextSplitter.split(documents);
    }
}
```

MyController：
```java
@RestController
public class MyController {
    @Autowired
    private MyMarkdownReader myMarkdownReader;

    @Autowired
    private MyTokenTextSplitter myTokenTextSplitter;

    @GetMapping(value = "/ai")
    public List<Document> generate() {
        List<Document> documents = myMarkdownReader.loadMarkdown();
        return myTokenTextSplitter.splitDocuments(documents);
    }

}
```

## 结论
可以看到：
1. 标题与正文是分离的，标题在元数据里，正文在text里
2. 如果一段文字超过了chunk size，那么这段文字会被切分成几块；反之则是在1块中返回全部文字
3. 如果标题后面接着标题，前面的标题会被忽略掉，因为`MarkdownDocumentReader`中标题会被放在metadata里，而如果该标题下没有正文，这一段会被直接丢弃。有两种方法解决：一种是修改原始文档，添加正文；一种是自定义markdown的拆分行为
4. 每段文字的长度都有上限，如果chunk size大于这个上限，那其实不管值设为多少，结果都是一样的；有区别的的只是值小于这个上限会分成多少块

怎么定chunk size：
- 如果每段文字的长度上限不高，可直接定为最大值
- 如果上限过高，则需要综合每段文字的长度来设置一个折中值，比如每段文字长度上限的中位值
- 当然长度越短，需要切分的块就越多；长度越长，需要切分的块就越少

## 注
### 标题被忽略解决方法
本文是为了验证对chunk size的拆分行为，因此使用`MarkdownDocumentReader`

通过自定义解析逻辑，不用`MarkdownDocumentReader`来解决标题问题：

MyMarkdownReader：
```java
@Component
public class MyMarkdownReader {
    private static final Pattern HEADING = Pattern.compile("^(#{1,6})\\s+(.*)$");

    private Resource resource;

    public MyMarkdownReader(@Value("classpath:reader/验证素材-星槎精工2026年度经营与财务分析报告.md") Resource resource) {
        this.resource = resource;
    }

    /**
     * 自定义解析
     *
     * @return List<Document>
     * @throws IOException
     */
    public List<Document> loadMarkdownCustom() throws IOException {
        String[] lines = resource.getContentAsString(StandardCharsets.UTF_8).split("\n");
        List<Document> documents = new ArrayList<>();
        String[] titles = new String[7];
        StringBuilder sb = new StringBuilder();

        for (String line : lines) {
            Matcher m = HEADING.matcher(line);
            if (m.matches()) {
                flush(documents, titles, sb);
                int level = m.group(1).length();
                titles[level] = m.group(2).trim();
                for (int i = level + 1; i < titles.length; i++) {
                    titles[i] = null;
                }
            } else {
                sb.append(line).append("\n");
            }
        }
        flush(documents, titles, sb);
        return documents;
    }

    private void flush(List<Document> docs, String[] titles, StringBuilder body) {
        String text = body.toString().trim();
        body.setLength(0);
        if (text.isEmpty()) {
            return;
        }
        String path = IntStream.range(1, titles.length)
                .filter(i -> titles[i] != null)
                .mapToObj(i -> titles[i])
                .collect(Collectors.joining(" > "));
        docs.add(new Document(path + "\n" + text, Map.of("title", path)));
    }
}
```
