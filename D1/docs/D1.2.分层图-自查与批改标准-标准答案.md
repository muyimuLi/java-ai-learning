# LLM 应用分层图 ｜ 自查与批改标准

> 用法：先看第一节的标准，自己改一遍；改完再看第二节的参考内容对照。
> **先自己改，别一上来翻答案。**

---

## 一、达标标准：每一层都要能回答这三个问题

1. **它对外提供什么？**（一句话，说职责，不要说动作）
2. **它的典型组件是什么？**（3–5 项，不要堆）
3. **它不负责什么？**（这一条最能体现你是真懂了）

如果五层里有的层写职责、有的层写动作，说明还没归纳好。

---

## 二、参考内容（对照用，不是唯一答案）

| 层   | 负责什么 | 典型组件 | 不负责什么 |
| --- | --- | --- | --- |
| **交互层** | 收用户输入、把结果呈现回去 | 网页 / App、后端接口（含 SSE 流式）、鉴权 | 不决定怎么回答 |
| **编排层** | 决定"做什么、按什么顺序做" | 路由（要不要检索）、工作流、Agent 循环、多步规划、提示词组装 | 不实现具体的检索或调用能力 |
| **能力层** | 一项项具体的本事 | **RAG 检索**、Advisor 链、工具调用、记忆管理、输出校验与重试 | 不关心 HTTP，也不关心模型是哪家厂商 |
| **模型层** | 把输入变成输出 | Chat 模型（DeepSeek）、Embedding 模型（百炼 text-embedding-v4）、重排模型 | 不存你的业务知识，不记对话历史 |
| **数据层** | 知识从哪来、存在哪 | 原始文档、切块、向量、元数据、会话历史、向量库（pgvector） | 不做推理，不做决策 |

## 三、三道必答题

这三题才是这个练习真正的考点。答不上来，图填得再整齐也没用。

### 题 1：微调在哪一层？

**答案：它不在这个图上。**

这张图画的是**运行时**链路——用户提问到拿到回答之间发生了什么。而微调是**训练时**行为，它改变的是模型层内部的权重，不参与一次请求的流转。

画法上要么不画，要么从图外画一个箭头指向"模型层"，标注"训练时"。

**分清"运行时"和"训练时"，是这道题的唯一目的。** 面试官很爱挖这一刀：很多人张口就说"我们的方案是 RAG + 微调"，但说不清这两件事分别在什么时机发生。

### 题 2：离线链路在哪？

知识入库发生在**用户提问之前**，是一条独立的链路：

```
文档上传 → 解析 → 分块 → 向量化(Embedding 模型) → 入库(数据层)
```

它横跨模型层（Embedding）和数据层。很多人的图只画了在线链路，面试被问"你的知识库怎么更新、更新后要重建索引吗"就答不上来。

### 题 3：Advisor 在哪一层？

**它不是一个层，是一个可以挂很多能力的挂点（横切插槽）。**

它挂在能力层，可以承载日志、RAG 检索、重试、记忆、输出校验。所以画成"能力层里的一个组件"可以，画成"单独一层"就错了。

## 四、常见错误自查

| 错误  | 为什么错 |
| --- | --- |
| Embedding 放在数据层 | Embedding 是一个**模型**，产出向量；**存**向量的是数据层 |
| "检索"放在数据层 | 数据层负责"存和取"，"检索并把结果拼进提示词"是**能力层**的动作 |
| 向量库放在能力层 | 向量库是**存储**，属于数据层 |
| 只画在线链路 | 缺离线链路，回答不了"知识库怎么更新" |
| 把 Prompt 当成一层 | Prompt 是贯穿性的，主要归属编排层 |
| 每层写的是"动作"而不是"职责" | 说明还没归纳，只是在罗列流程 |
| 没有箭头 / 看不见依赖方向 | 分层图一半价值在"层之间的边界和依赖方向" |

---

## 五、达标线

- 五层都能用"职责 + 组件 + 不负责什么"的格式说出来
- 三道必答题都能答上来
- 能画出离线链路
- 能说清一个请求从用户输入到流式返回，途经哪些层

达到这四条，这张图就可以直接拿去面试了。
